# Releases

Depo UI uses Changesets and lifecycle metadata to make package changes reviewable. A release note should explain the user impact, affected package, migration path, accessibility or visual implications, and support window.

## Lifecycle-aware documentation

- Proposal is a design discussion and is not a public API.
- Trial is available for learning and can change with explicit feedback.
- Stable has passed design, API, accessibility, responsive, theme, localization, visual, Figma parity, production usage, and ownership gates.
- Deprecated names its replacement, migration or codemod, warning, and removal window.
- Removed is only published after the deprecation and migration evidence is complete.

Versioned Docs must keep the API reference tied to the package version that produced it. Generated metadata identifies its source files and hash so a release can detect stale documentation before publish.

The release automation and approval route are defined in `governance/` and `.github/`.

## Public npm distribution

The product-facing install is:

```bash
pnpm add @depo-ui/react
```

```tsx
import '@depo-ui/react/css';
import { Button, Card } from '@depo-ui/react';
```

The first public release is versioned through Changesets and the reviewed version PR. Publishing is a separate, manually dispatched workflow protected by the `release` environment and the exact `publish` confirmation. The workflow uses npm Trusted Publishing with GitHub Actions OIDC and provenance; a narrowly scoped `NPM_TOKEN` is a bootstrap-only fallback for creating packages that do not yet exist. No token is committed to the repository.

Before the first provenance-enabled public publish, maintainers must make `seipass/depo-ui` public, create or own the `depo-ui` npm organization/scope, configure the `release` environment reviewers, and configure one npm Trusted Publisher per public package. See the repository release runbook for the current `npm trust github` command.

## Release checks

Maintainers run `pnpm governance:check`, `pnpm release:status`, `pnpm docs:check`, `pnpm figma:check`, `pnpm test`, and `pnpm build` before a version PR. The governance check also installs a packed token package in an isolated Consumer fixture. It is a dry run: registry publication requires the protected `release` environment and the manual workflow.

Rollback uses a forward fix or an explicit patch/revert release. Packages are never unpublished as a recovery shortcut.
