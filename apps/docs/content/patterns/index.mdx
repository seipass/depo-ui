# Patterns

Patterns describe what a user is trying to accomplish. They compose Components and Foundations while leaving product data fetching, routing, authentication policy, and domain rules in the consuming application.

Every Pattern reference records its purpose, Component composition, state transitions, error and recovery behavior, responsive adaptation, and accessibility concerns. The references are generated from `specs/patterns/*.json` and their narrative Markdown files.

Prefer a Pattern when a workflow has repeated state and recovery decisions. Prefer a Component when the requirement is a reusable interaction or visual primitive.
